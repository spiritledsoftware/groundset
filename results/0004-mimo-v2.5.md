# Trial 0004: MiMo v2.5

Date: 2026-08-26

Model: `opencode-go/mimo-v2.5`, high reasoning effort

## Protocol correction

The first six runs used the agentic protocol. All passed hidden checks, but the no-evidence WebSocket run searched Cargo's registry source outside the candidate. That violated the isolation rule and invalidated that comparison. On the custom path rejection task, the no-evidence run needed a compiler-guided rewrite while the oracle run compiled on its first implementation.

The benchmark was rerun with the one-shot protocol. `PROMPT.md`, `src/lib.rs`, and `Cargo.toml` were supplied up front. Only edit and write tools were available. Cargo and hidden tests ran after the model stopped.

## First one-shot pair

| Task | No evidence | Oracle | No-evidence tokens | Oracle tokens | No-evidence elapsed | Oracle elapsed |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| User lookup | Pass | Pass | 9,091 | 9,036 | 29.3 s | 20.9 s |
| Custom path rejection | Compile failure | Pass | 47,701 | 20,035 | 112.9 s | 39.3 s |
| WebSocket message | Pass | Pass | 6,342 | 7,092 | 14.6 s | 29.1 s |

The custom rejection failure built an unnecessary custom extractor and referenced `serde_json`, which was available only as a development dependency. The oracle implementation used `Result<Path<u64>, PathRejection>` directly and passed.

## Custom rejection replication

Three one-shot runs were made per condition, including the first pair above.

| Condition | Hidden verification | Median tokens | Median cost | Median elapsed |
| --- | ---: | ---: | ---: | ---: |
| No evidence | 1/3 pass | 36,580 | $0.00319 | 121.8 s |
| Oracle | 2/3 pass | 14,884 | $0.00110 | 39.3 s |

No-evidence outcomes were one compile failure, one provider stall that produced no edit, and one pass. Oracle outcomes were two passes and one compile failure caused by destructuring `Result<u64, PathRejection>` as `Path(id)` instead of receiving `Result<Path<u64>, PathRejection>`.

This is the first result in the repository where evidence improved both correctness and median resource use. The sample is still too small, and the model showed substantial run variance. The next useful step is more tasks built around obscure APIs, not more repetitions of this single Axum case.
